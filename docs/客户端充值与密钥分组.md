# 客户端充值与密钥管理

## 交互

API 密钥列表点击分组立即显示可搜索下拉，选择不同分组即提交。Enter 选中、上下键移动、Escape 关闭；失败保留原分组和错误信息。采用 Sub2API 品牌配色及品牌 SVG，显示分组说明、默认/专属倍率与当前选择。品牌图标来源和 LGPL 许可在 `app/THIRD_PARTY_NOTICES.md`，许可随前端资源分发。

“创建密钥”使用 Molly 表单，提供名称、供应商筛选、分组、自定义密钥、总额度、IP/CIDR 白黑名单、5 小时/1 天/7 天额度及有效天数。高级选项默认关闭。取消不创建；提交期间禁用重复提交和关闭；失败保留草稿。创建成功插入掩码行并刷新列表。实际密钥复制与 CC Switch 导入继续使用原生按 ID 读取流程。

每条密钥提供“删除”按钮，确认提示说明密钥失效且无法撤销。取消不发送请求，删除期间禁止重复提交与关闭；失败保留记录和具体错误，超时提示刷新确认。服务端确认后删除列表项，防止并发旧刷新响应恢复该项；焦点回到“创建密钥”。不会自动移除 CC Switch 供应商或改写本机工具配置。

充值仍位于概览的用量之后，余额与前往充值入口保持内部跳转。页面使用 Molly 公共 token 和组件，分为余额充值、订阅套餐、我的订单。提供金额、付款方式、费用与到账预估、在售套餐、订单分页、待支付取消、手动查询和到账刷新。人民币等支付币种与美元余额分别标识；套餐按服务端汇率换算，最终金额以创建结果为准。赠送和折扣模式分别计算，不把赠金当成现金付款。

订单创建后自动打开独立、非模态支付窗口，窗口右上角仅保留 X；控制台继续操作与拖动，切换菜单不会关闭支付窗口。二维码订单使用官网固定 `/payment/qrcode` 落地页，银行卡等使用订单专属支付目标；原生详情仍可查看二维码并重新打开支付窗口。窗口关闭不取消订单，关闭后查询状态；取消订单是另一个明确操作。旧会话无法恢复支付链接时保留订单查询和取消入口，不能静默新建替代订单。

支付宝与微信的选中态分别使用品牌蓝、绿。充值页沿用普通控制台工作区的纵向滚动，小窗口可到达底部付款与订单操作。

订阅套餐遵循 Molly 官网二次开发的实际语义：`for_sale` 控制上架目录，`user_visible` 控制能否购买。`for_sale=true,user_visible=false` 仍展示名称、价格和权益，按钮显示“不可购买”并禁用；`for_sale=false` 为下架，不显示。两个普通用户接口 `/payment/plans` 和 `/payment/checkout-info` 都已返回上架但不可购买的套餐及这两个字段，无需管理员接口、额外权限或服务端改动。此前客户端把字段含义读反而过滤掉停售套餐，现已修正。下单前原生端重新获取信息并同时校验两字段。旧版上游省略字段时默认上架/可购买，显式 false 始终保留。

语义与返回数据已核对本机二开源码 `backend/internal/service/payment_config_plans.go` 的 `ListPlansForSale`、`backend/internal/handler/payment_handler.go` 的两个目录处理方法，以及 `backend/internal/service/payment_order.go` 的 `validateSubOrder`。服务端既有 `payment_plan_availability_test.go` 也覆盖上架但不可购买套餐仍出现在两个目录的情况。

## 接口

密钥实现为 `app/src-tauri/src/key_groups.rs`：GET `/groups/available`、`/groups/rates`；切换前重新检查可用组，PUT `/keys/:id` 只提交 group_id；创建 POST `/keys` 使用明确字段白名单，验证名称、ID、自定义密钥、IP/CIDR、非负额度和有效期。删除通过 DELETE `/keys/:id`，限制 console 来源、校验正整数 ID，服务端校验当前账户归属。写操作不自动重试。多个列表项共享同时发出的分组读取请求，不缓存保存权限。

充值实现为 `app/src-tauri/src/payments.rs`：GET `/payment/config`、`/payment/checkout-info`、`/payment/orders/my`、`/payment/orders/:id`；POST `/payment/orders`、`/payment/orders/:id/cancel`、`/payment/orders/verify`。若 checkout-info 明确返回 404，则使用固定 config/plans/limits 接口兼容旧服务；其他错误不降级。所有路径由 Rust 固定构造，所有管理命令限制 console 窗口，前端没有通用账户 API 代理。

下单前重新获取付款方式和套餐，服务端最终验证可用性、限额、汇率、手续费和优惠。POST 不自动重试，未知下单结果要求先核对订单记录。前端只在页面可见且存在待处理订单时查询状态，结束、切页、弹层遮挡或卸载后停止；手动“我已支付”才向上游核验接口请求检查。COMPLETED 才提示到账并刷新账户信息。

## 支付隔离

- 独立 Tauri 原生窗口承载原始 Wry WebView2，不注册为 Tauri WebView，不注入通用 Tauri IPC；网页唯一的本机消息是无参数关闭自身窗口。
- 每次打开支付页面使用独立临时 InPrivate 会话；退出登录关闭全部支付视图、清理浏览资料和内存支付会话。
- 短期 Access Token 与用户信息仅注入 Molly 官网主框架；不向第三方/嵌套框架注入、不共享 Refresh Token、密码或 API 密钥。
- 支付 URL、client_secret、resume_token 与 Airwallex recovery 留在 Rust 内存，控制台按订单 ID 请求打开。恢复数据只写入临时官网会话的 localStorage，字段按 Sub2API 官方支付落地页核对。
- 原生每次打开都重新检查当前账户和订单状态，禁止跨账户、已结束订单复用会话。创建、取消、打开与退出使用同一支付锁。
- 每个前端支付组件有唯一视图 ID，事件标记此 ID；延迟返回的旧组件关闭操作或旧页面事件不能影响后来打开的窗口。同一订单窗口可重新激活，关闭 X 会清理临时会话及其弹出窗口。
- 导航仅允许公网 HTTPS 域名；拒绝本地 IP/文件/活动内容/自定义协议，禁止网页下载。页面状态事件仅包含域名，不携带支付 URL 的参数。
- 支付弹窗沿用临时环境，最多四个；仅接受固定的关闭信号，不分派本地命令。主题与短期登录续期由宿主管理。
- 生图 sandbox、CC Switch、桌宠的权限与数据目录不变。

## 验证

浏览器预览使用明确标识的模拟套餐、订单和掩码密钥，不能创建真实订单或创建、删除真实密钥。测试不读取真实账户凭据、不修改 Agent 配置、不付款、不重启运行中的桌宠。

```powershell
# app 目录
npm test
npm run build
npm run check:design
npm run check:design -- --dark
# app/src-tauri 目录
cargo test --offline --lib --jobs 1
cargo run --offline --example recharge_smoke --jobs 1 --features recharge-smoke
```

设计检查覆盖登录、七个控制台入口及概览子页，深浅主题和 960×640、1180×760、1440×900；包括分组取消/搜索/键盘立即选择/保存失败、创建密钥取消与掩码结果、删除确认/取消/失败/重复点击/最终空列表/旧刷新响应过滤及焦点恢复、模拟下单/查看/取消、独立窗口自动打开/导航后保持/控制台不被 inert 锁定与付款方式配色、长名称换行。滚动条在 Chromium 中统一使用 WebKit 伪元素实现 6px 滑块和无箭头；将标准 scrollbar 属性重置为 auto，避免 Windows 原生箭头覆盖规则。

原生单测覆盖写参数、跨窗口拒绝、支付目标、敏感字段过滤及套餐价格变化；独立隐藏 WebView2 测试使用临时配置与模拟令牌检查跨来源 iframe、续期、弹窗、独立窗口无 owner/仅关闭控制、控制台可移动与关闭清理。接口字段参考 Wei-Shaw/sub2api commit `458b92abd4b0b09d123d4c6727dd8d59060bd883`。

真实支付渠道、第三方验证和到账未自动执行；发布前需在重新编译的桌面客户端中做正式渠道联调。若官网升级更改支付路由、存储键或字段，需要同步检查此适配。
