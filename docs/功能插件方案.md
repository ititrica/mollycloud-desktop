# 控制台功能插件

2026-10-02。适用于 CC Switch、生图工作台、Skill 管理器。

## 用户入口与行为

在控制台「设置 → 功能插件」管理三个工作台：安装随附版本、卸载、检查官方更新、安装适配更新、恢复上一版本。首次迁移保留三个现有功能；卸载后的导航保留安装入口。卸载先提示保存未完成编辑，再关闭对应 iframe。浏览器设计预览只模拟本地安装状态，不下载、不调用真实 Agent 配置。

配置、CC Switch 供应商与备份、技能库、已部署的 Skills、生图配置与图片记录均属于用户数据，卸载不删除。已经写入外部 Agent 的配置也不会因卸载插件而撤销。卸载后重新安装继续使用原数据。

安装/卸载立即写入插件记录，不随通用设置的「取消」回滚。CC Switch 和 Skill 管理器涉及原生后台服务，界面明确提示需要重启的情况。卸载立即阻止新的插件命令；已启动的后台服务随正常退出完成清理，下一次启动不再初始化。不会自动重启桌宠。生图插件可以即时安装与卸载；关闭工作台会取消该工作台中的请求。

## 实际独立更新边界

这是「独立工作台资源包 + 宿主原生适配器」架构。三个工作台的 HTML/JS/CSS 可在不重新打包主应用的情况下安装、更新、回退；原生 CC Switch / Skills Rust 代码目前仍链接在 Molly 中，原生接口或行为升级需要更新主程序，不能把上游桌面 EXE 当作插件执行。卸载不会缩小 Molly 可执行文件，也保留安装包随附的离线恢复资源。

`app/plugins/definitions.json` 是唯一功能目录，记录官方仓库、随附版本、资源路径、宿主版本要求和 `adapterApi`。插件有独立适配版本（例如 `3.20.4-molly.1`），同时标明对应上游版本。不能只修改版本号宣称兼容新原生接口；维护者必须完成适配和测试后发布。

客户端从三个上游 GitHub 仓库的 releases/latest 查询官方版本，从固定 Molly 适配目录查询可安装包。官方有新版而适配包尚未发布时，显示两者真实状态；不会安装上游独立客户端。原生接口不兼容时，阻止安装并提示先升级 Molly。

## 存储、加载和安装事务

- 记录：Molly 应用数据目录 `plugins/installed.json`。
- 下载资源：`plugins/packages/<id>/<SHA-256>/`。代码与用户数据目录分离。
- 安装顺序：固定 HTTPS 来源 → 限长下载 → 大小与 SHA-256 校验 → 临时目录解压 → 验证 plugin.json → 资源目录移动 → 原子替换安装记录。
- 发布目录和包内的 id、version、upstreamVersion、adapterApi、hostVersion 必须相同；包只允许前端静态文件，不允许 EXE/DLL/脚本启动器。
- 拒绝跨目录路径、Windows 保留名称、符号链接、重复文件、解压数量/大小超限。失败不会切换已安装版本。保留上一版本供回退。
- 卸载删除资源引用；下次启动只清理本插件代码目录中不再引用的版本，避免删除仍在读取的资源。损坏的安装记录禁用插件管理并显示错误，不阻止登录和桌宠启动，也不覆盖损坏记录。
- 更新信任固定 `https://desktop.veriolink.com/plugins/` 的 TLS 来源与该目录中的 SHA-256；当前没有额外离线签名系统，发布桶写权限就是代码发布权限。

CC Switch / Skills 继续运行在控制台同源 iframe，使用原有命令白名单与私有目录适配。原生发行版通过控制台资源请求拦截加载安装的资源；开发模式通过仅服务插件静态文件的 Vite 路由使用相同安装记录。`molly-plugins/<id>/` 不暴露用户配置。生图始终通过 `molly-image` 独立来源 + 不含 allow-same-origin 的 sandbox + 受限 MessageChannel 加载；更新不改变该边界，不提供通用 IPC 或自动账户密钥。

## 发布适配包

1. 在 vendor 中更新对应上游固定版本，保留并审查 Molly 适配。
2. 更新 definitions.json 的上游与适配版本；涉及原生接口时修改 adapterApi 并发布主程序。
3. 执行 `npm run build`、原生/前端测试及视觉检查。CC Switch 升级还要执行 `npm run check:ccswitch-upgrade`，保留官网地址、连通性、余额查询、网页导入和私有数据保护回归。
4. 在 app 目录执行 `npm run release:plugins`。维护者机器需 Python（只用于 ZIP 打包；终端用户不需要开发工具）。输出 `artifacts/plugin-release/` 中三个 ZIP、index.json、UPLOAD.md。
5. 将 ZIP 上传到 `mollycloud-desktop` 桶的 `plugins/`，验证大小/摘要和可访问性，最后上传 `plugins/index.json`。目录使用 `Cache-Control: no-cache`。客户端固定检查 `https://desktop.veriolink.com/plugins/index.json`。

包包含上游许可证和第三方声明。该流程不自动上传任何文件，也不会拉取、构建或执行未经适配的上游源码。

## 验证

`cargo test --lib console_plugins::tests` 覆盖兼容性、来源、危险 ZIP、安装/卸载/回退、失败原子性和数据保留。`cargo run --example plugin_smoke --features plugin-smoke` 使用临时目录和隐藏的 WebView2，实际加载安装后的 HTML/JS，验证同源桥接、回退和卸载后 404。`npm run check:design` 覆盖三种窗口大小、设置弹层、插件预览生命周期、菜单和内容滚动。
