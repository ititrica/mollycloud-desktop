# 灵动岛内置方案

## 入口与生命周期

NetSpeed Dynamic 2.4.6 静态集成到 MollyCloud。菜单依次为概览、API 密钥、CC Switch、Molly助手、灵动岛、生图工作台、Skill 管理器。灵动岛固定可用，不受 CC Switch 等三个功能插件的安装状态影响。

控制台遵循 `design-system/molly-desktop/MASTER.md`，使用共享字体、色彩、圆角和滚动条；灵动岛本体使用独立透明 WebView 窗口，不导入控制台布局，也不修改 Petra。入口为 `app/island.html`，窗口标签 `netspeed-widget`。岛体的深浅色是独立显示设置，控制台配色仍跟随 MollyCloud。

启动时恢复灵动岛开关、位置和外观；默认显示网速。灵动岛随 MollyCloud 进程退出。关闭控制台到托盘时继续工作，退出程序时一起结束。开机启动只由 MollyCloud 的控制台设置注册，NetSpeed 不再有单独自启动、单实例、托盘或更新入口。

## 保留的能力

- 实时上传/下载速度、CPU/内存、流量记录与图表。
- 网速、资源、媒体、FPS、系统时间和三槽自定义组合显示。
- Windows SMTC 播放控制、封面与歌词，含通用媒体、常见播放器和浏览器。
- 系统通知、剪贴板链接、静默、全屏隐藏与悬停唤出、位置锁定/重置。
- 宽高、缩放、圆角、不透明度、弹性动画、流光和歌词延迟。
- 可选任务栏显示、游戏 FPS 采集，以及本机活动 API。

流量来自所有本机网卡的累计计数差值，并按实际采样间隔计算速度。首次采样和网卡计数重置不计入新增流量。记录仅覆盖 MollyCloud 运行时段，最多保留 366 天，每 15 秒保存一次；VPN/虚拟网卡可能与物理网卡重复计数。它不代表 MollyCloud 账户用量。

## 常驻系统时间

“显示与交互 → 常驻内容”包含实时网速、CPU / 内存、媒体与歌词、游戏 FPS、系统时间、自定义组合。选择“系统时间”时单独显示本机 24 小时制时分秒；它也作为自定义组合的一个槽位，可与网速、资源或媒体封面同时显示，不再提供独立的附加时钟开关或额外增加 80px 窗口宽度。

单独时间沿用基础宽高，自定义组合沿用组合宽度；总开关和全屏隐藏优先，静默模式仍保留含时间的内容。通知与任务活动按既有优先级临时覆盖时钟，结束后恢复当前模式；隐藏或被覆盖时停止计时器，恢复时重新读取本机时间。旧版 `nsd_show_system_time=true` 偏好迁移为自定义组合：原单内容模式保留该内容并加入时间；已有组合优先将时间填入空槽，三个槽位均满时以时间替换第三项，前两项保持。迁移完成删除旧附加开关键。新单独模式使用 `nsd_system_time`，组合槽位使用 `time`，均保存在既有私有存储中。

控制台横向选单复用概览的 `subnav.css`、`navigationMotion.ts`，与 Skill 管理器共用样式、滑动下划线、内容过渡和减少动态效果处理。

## 隔离与外部服务

偏好和流量数据保存在 MollyCloud 自有 WebView2 用户目录，键前缀 `mollycloud:netspeed:`。浏览器预览键前缀为 `mollycloud:preview:netspeed:`，不调用原生服务。独立版 NetSpeed 数据不迁移、不改写。

灵动岛权限只包含窗口、事件、原生右键菜单与 HTTP(S) 链接打开，不授予 autostart/updater/shell。原生灵动岛服务仅接受控制台和灵动岛两个窗口的调用。窗口显示指令锁定灵动岛标签，动画不能调整控制台或 Petra。控制台、充值和生图 sandbox 的既有边界不变。

系统通知、剪贴板链接、任务栏和活动 API 默认关闭；音频频谱在首次实际显示需要时初始化，仅处理频谱数据。启用系统通知时，Windows 可能要求授权。歌曲封面和歌词沿用上游服务；远程封面限上游 CDN、限大小并转为图片数据，不扩大控制台 CSP。

任务栏辅助组件绑定本机 47291，FPS 使用 47292，活动 API 使用 47300。端口被独立版或其他进程占用时返回错误，不关闭其他进程。活动 API 仅在用户开启后监听 127.0.0.1，关闭时停止并清空活动，不接受浏览器 Origin 请求。协议见 `vendor/netspeed-dynamic/API.md`。本机原生工具可通过它提交显示信息，它不是远程控制接口。

辅助程序来自固定上游提交，打包前和运行前都校验哈希。安装包只允许这两个固定资源例外，前端、模型目录仍禁止 EXE/DLL/脚本，用户配置与密钥仍禁止打包。辅助程序功能受 Windows、游戏、播放器及其运行环境影响，不保证所有游戏都能采集 FPS。

## 验证

- `npm test`：采样计数重置、损坏历史恢复、端口/辅助服务失败保留原设置；时间模式/组合持久化、旧时钟迁移、跨午夜/系统调时、隐藏及卸载停止刷新。
- `npm run check:design -- --island-clock`：临时浏览器中加载真实岛体组件，以官方 Tauri mock 验证独立时间/自定义组合、模式切换尺寸、活动覆盖与恢复、静默、全屏与总开关、重载及旧偏好迁移；不操作真实桌宠或系统服务。
- `npm run check:design -- --motion`：概览、灵动岛与 Skill 管理器统一样式、快速切换及减少动态效果回归。
- `npm run build`：类型检查、生产构建、依赖资源与敏感文件扫描。
- `npm run check:design` 与 `npm run check:design -- --dark`：三种窗口尺寸、登录、全控制台页面与灵动岛设置。
- `cargo check --lib --jobs 1`。
- `cargo run --example netspeed_smoke --features netspeed-smoke --jobs 1`：临时用户目录、隐藏原生窗口，检查启动、设置同步、禁用保持、窗口权限与退出；不启动辅助 EXE、不读取真实剪贴板/通知/媒体，也不重启用户桌宠。
- `cargo run --example netspeed_smoke --features netspeed-smoke --jobs 1 -- --startup`：临时用户目录中默认开启岛体，同时启动正式后台监测；验证自动显示、位置与尺寸、展开、关闭、重新唤出及打开控制台。四个测试窗口共享事件循环，主线程心跳停滞 8 秒即失败，45 秒整体超时；不重启用户桌宠。

安装包保持当前项目版本 0.1.6；本次请求未指定新的版本号。构建产物与校验值另存 `artifacts/releases/0.1.6-netspeed/`。

### 安装后未响应修复

原安装包的 `show_window_no_activate` 是同步插件命令。Tauri 调用插件命令时持有插件管理器锁，Win32 `ShowWindow` 同步触发窗口事件后，事件分发又需要取得该锁，导致共享窗口线程死锁。隔离测试已复现：调用停在 `show_window_no_activate`，主线程心跳超时。之前仅测试关闭岛体的路径，漏掉了默认显示分支。

所有涉及窗口的内置命令改为异步，先退出插件分发再操作窗口。显示操作在 UI 线程执行，临时使用 `WS_EX_NOACTIVATE` 防止抢焦点，通过 Tauri `show()` 同步内部可见状态，再恢复原扩展样式。直接调用原生 `ShowWindow` 会留下框架中“窗口仍隐藏”的状态，后续置顶或样式更新可能再次隐藏窗口，因此也一并修正。

启动诊断日志提前到控制台模块初始化之前，并记录创建控制台及后台服务就绪阶段。新回归测试使用与安装版一致的透明、无边框、无阴影窗口属性，检查实际窗口尺寸和可见性（上游的收起行为会缩成 1×1），而非仅检查 Vue 挂载或 IPC 返回。

修复后默认开启和关闭两种隔离启动检查通过；38 项前端/脚本测试及生产资源检查通过。重新构建的安装包位于 `artifacts/releases/0.1.6-netspeed-hotfix/`，NSIS 22,004,140 字节，MSI 28,852,224 字节；MSI 版本、主程序大小和资源文件表已验证，并附 `SHA256SUMS.txt`。仍为 0.1.6，需手动覆盖安装，不会以相同版本触发自动更新。本次未覆盖用户现有安装，未发布到 GitHub 或 R2。
