# Codex 任务监听与界面调整

实施日期：2026-09-16。

## 1. 本地任务监听

入口为 `app/src-tauri/src/codex_activity/`，在 MollyCloud 后端启动时初始化。使用 `notify` 的 Windows 文件系统通知，按文件维护读取偏移和未完成行；合并连续写入事件，不定时轮询会话正文。

自动发现用户默认 `.codex/sessions`、进程环境中的 `CODEX_HOME/sessions` 和内置 CC Switch 当前实际 Codex 配置目录。运行期间每 30 秒仅重新发现配置目录，不扫描已有会话文件；已发现的目录继续监听。目录尚未创建时监听现存父目录，出现后切换为递归监听。此前保存的附加 Codex 目录继续监听；悬浮球不再提供任务列表和目录管理入口。

首次扫描最近 7 天修改的文件；历史已完成任务不产生新未读，仍在运行/等待输入的任务会显示。启动后产生的完成事件进入未读。未读与用户添加的目录保存为 MollyCloud 私有数据目录下的 `codex-activity.json`，以临时文件原子替换，重启恢复未读。已经读取的终态在内存保留，用于去重文件移动与重复事件。

保留事件类型、线程/轮次/工具调用标识、时间戳、步骤类别、命令退出码与明确提供的模型/供应商名称。按最新需求额外提取 Codex 公开摘要的首行标题（最多 160 字符），思考步骤优先原文显示，例如“Appending theme token CSS”。摘要正文、原始推理、加密内容、消息正文、工具参数、工具输出和错误详情不进入任务状态、前端事件或持久化文件。标题仅用于当前思考阶段，开始工具步骤或结束任务时清除，不进入步骤历史与未读持久化。缺少模型信息时显示“自定义模型”。不读取认证文件，不调用额度接口，不启动 App Server，不安装 Hooks/插件，不修改 Codex 配置。

按线程和轮次归并任务。同一线程开始新轮次时替换此前轮次；不同线程独立跟踪。头顶胶囊由正在运行或等待输入的任务触发，优先显示等待输入，其次选择最近更新的运行任务。主动中止显示“已停止”，作为普通未读动态。运行中从原位置移动到模型头顶，左侧保留圆形余额，右侧显示实时步骤；宽度随文字变化，最多 280px，超长省略。移除任务数量角标。任务期间悬停、聚焦或点击均不展开下拉框，也不保留额外面板命中区域；若原有圆球详情已打开，进入任务时立即收起。小球使用单个白色圆点，胶囊使用两道高光、相隔半圈，均沿完整边框连续逆时针运动，不往返、不带分段尾迹。CSS 圆角运动路径自动适配宽度，连续径向渐变经中空遮罩裁成边框高光；白色亮边和白色柔光为主，只保留淡浅绿外晕。胶囊高光中央最厚，两端逐渐收尖。胶囊以固定 136px/秒沿边框移动，相比上一版 160px/秒再减慢 15%；光带长 52px、中央亮边厚 2.5px。空闲小球以 24.5px/秒移动，约 5 秒一圈；单个圆点直径 5px，保留纯白亮芯与外围白色柔光。ResizeObserver 根据实际边框周长计算动画周期，胶囊越长一圈所需时间越长，移动速度不随文字长度变化。两道高光继承父层唯一的动画进度，第二道固定偏移半圈，不再依赖各自的启动时间和负延迟，避免小球切换胶囊时错位。柔光在遮罩裁切后由外层渲染，层级高于左侧余额圆盘，不遮挡正文或接收指针事件。低余额独立警告不显示光效，减少动态效果偏好下高光停止运动，胶囊的两道高光保持相对位置。任务完成后头顶胶囊显示“任务已完成”20 秒，期间新任务立即取代完成提示；重复快照或清除未读不会重新计时，启动历史完成任务不触发提示。存在其他活动任务时继续显示活动任务。保留期间仍不展开下拉框。20 秒到期、任务失败或停止后恢复左上侧小球与 148px 圆形悬停面板，未读终态不阻止恢复。无账户余额时仍显示活动任务。空闲大圆球仅显示余额和今日 Token 消耗，移除“Codex 任务”文案及其任务列表入口；任务状态和步骤信息仍保留在 Molly 只读工具中。

### 兼容边界

[官方 App Server 文档](https://developers.openai.com/codex/app-server)描述的是实时协议，本实现不连接该协议。会话 JSONL 属于兼容格式：仅日志明确写出的生命周期、审批和输入请求可识别；未落盘的审批、重试或进程崩溃不能凭空推断。输入请求显示“需要输入”，后续真实任务进度（思考、重试、命令、工具、回复等）、答复或轮次结束会立即替换等待状态，无论问题是否已回答或超时。异步提问工具的立即确认返回、Token 统计和未知事件本身不解除等待。已继续工作的任务不会被迟到答复回退为“正在思考”，已结束的任务也不会因此重新变为运行中。后续 Codex 格式变化可能需要更新独立解析器。步骤解析兼容 response_item 的 reasoning/function_call/custom_tool_call，以及 event_msg 的 item_started/item_completed、命令与修改事件；区分“正在思考”“正在重试”“正在运行命令”“运行了命令”等。命令失败只更新步骤，不直接把整个任务判为失败。重试仅依据明确重试事件或 will_retry 标记，不按等待时间推测。

未知事件忽略，损坏/超长行跳过，分别记录计数，不记录原始行、不把解析失败当作任务受阻。单行缓冲上限 1 MiB。截断、替换、移动和通知溢出后重新同步；读取/监听/保存错误保留在任务快照的 warning 字段，可通过 Molly 的悬浮窗只读工具获取。更新文件的读取限于通知时已存在的字节，持续输出不会无限阻塞事件处理。

标题兼容 `response_item.reasoning.summary[].text`（类型为 `summary_text`）与 `event_msg.item_started/item_completed` 中 `Reasoning.summary_text[]`。只取 Markdown 加粗或标题行中的标题，不回退显示摘要正文。本机会话中已核对到用户提供的“Appending theme token CSS”，两个字段均含同一标题。该方案读取落盘事件，标题尚未写入、未生成或格式不支持时显示“正在思考”等通用状态；工具完成显示“运行了命令”等类别提示。日志写入时机会带来延迟，不能保证与 Codex 内置宠物每一帧、所有内部状态文案完全一致。

## 2. Molly 助手

助手复用公共沉浸式工作区，与 CC Switch、生图工作台一致隐藏宿主页头。聊天区无外边距、边框、圆角或阴影，标题为 Molly，消息区独立滚动，输入区固定。公共侧栏、窗口标题栏、桌宠开关、设置齿轮和消息发送流程保留。沉浸式工作区不预留无用的外层滚动条槽。

新增只读工具 `get_floating_window_info`，读取悬浮窗使用的同一份实时显示状态：余额、今日 Token、胶囊当前进度原文、任务状态、完成保留截止时间，以及任务列表中的模型、供应商与最近八个步骤标签。控制台和桌宠 Molly 共用消息执行流程；无需账户登录即可读取任务状态，不扩大原生 IPC 权限。助手收到相关提问时调用该工具，不从旧对话猜测；标题按数据处理。输出采用字段白名单，不包含原始日志、命令/工具参数、输出或密钥。
