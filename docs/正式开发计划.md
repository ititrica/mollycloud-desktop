# 桌面 Live2D 客户端正式开发计划

> 项目正式名称：MollyCloud。
>
> 规划基线：2026-09-11 检查的 sub2api 提交 `9c30951e4aca86c4590a361a06d599b29c06caad`。
>
> 桌宠基线：Petra 0.2.3，固定提交 `9b4af14efc14696e4b249ecde1ad66008af502e0`。

## 1. 产品边界

桌面客户端是一个安装包、一个常驻进程，提供两个相互协作的窗口：

1. **Live2D 桌面模型窗口**：透明、无边框、可置顶、默认不出现在任务栏；负责模型渲染、动作播放和桌宠交互。
2. **用户控制台窗口**：标准窗口；负责登录、余额、订阅、API 密钥、Token 用量和 Molly 助手总开关。

第一版采用“高可靠只读控制台”：除登录、刷新会话和登出外，不创建、修改或删除 API 密钥，也不修改订阅或余额。写操作在后续版本单独设计确认与审计流程。

## 2. 已确认的输入

### Live2D 模型

用户提供的文字路径为 `C:\Users\ititr\Downloads\seethrough\_output-psd2live`，实际存在的目录是：

`C:\Users\ititr\Downloads\seethrough_output-psd2live`

已检查 `seethrough_output.model3.json` 的全部运行时引用，以下文件均存在：

- `seethrough_output.moc3`
- `seethrough_output.4096/texture_00.png`
- `seethrough_output.physics3.json`
- `seethrough_output.cdi3.json`
- `seethrough_output.idle.motion3.json`
- `seethrough_output.blink.motion3.json`
- `seethrough_output.nod.motion3.json`
- `seethrough_output.shake.motion3.json`

动作组为 `Idle`、`Blink`、`Nod`、`Shake`。模型包含头部角度、身体角度、眼睛开合、眼球、眉毛、嘴型、呼吸和头发物理参数。当前 `model3.json` 没有 `HitAreas`，所以首版采用“窗口交互区”；若要区分点击头部、身体等部位，需要补 HitArea 或实现像素级命中测试。

模型将通过导入脚本复制到项目资源目录并生成 SHA-256 清单。运行时不能依赖 Downloads 路径。

### sub2api

sub2api 是 Go + Gin 后端、Vue 3 前端，API 根路径为 `/api/v1`。当前源代码使用 `{ code, message, data }` 响应包裹，成功时 `code === 0`；授权请求使用 `Authorization: Bearer <access_token>`。

已确认的用户侧接口：

| 功能 | 方法与路径 | 首版用途 |
| --- | --- | --- |
| 服务健康 | `GET /health` | 启动和断线诊断 |
| 公开设置 | `GET /api/v1/settings/public` | 站点名称、验证码与登录方式 |
| 登录 | `POST /api/v1/auth/login` | 邮箱、密码及可选验证码凭据 |
| 两步验证 | `POST /api/v1/auth/login/2fa` | TOTP 二次登录 |
| 刷新会话 | `POST /api/v1/auth/refresh` | 轮换 access/refresh token |
| 当前用户 | `GET /api/v1/auth/me` | 用户资料、余额、并发和状态 |
| 登出 | `POST /api/v1/auth/logout` | 撤销 refresh token |
| 密钥列表 | `GET /api/v1/keys` | 密钥状态、额度、有效期、近期用量 |
| 订阅概览 | `GET /api/v1/subscriptions/summary` | 活跃数、到期时间和用量进度 |
| 订阅进度 | `GET /api/v1/subscriptions/progress` | 日/周/月额度窗口 |
| 用量总览 | `GET /api/v1/usage/dashboard/stats` | 请求数、Token、费用、RPM/TPM |
| 用量趋势 | `GET /api/v1/usage/dashboard/snapshot-v2` | 时间序列、模型和分组统计 |
| 密钥用量 | `POST /api/v1/usage/dashboard/api-keys-usage` | 批量读取各密钥用量 |

注意：上游前端存在 `GET /subscriptions/:id/progress` 的客户端函数，但普通用户路由并未注册该路径；本项目只使用已注册的 `/subscriptions/progress`。

## 3. 技术选型

### 桌面容器

采用 **Tauri 2 + Rust**，Windows 作为首发平台。前端采用 **Vue 3 + TypeScript + Vite + Pinia**。

理由：

- Tauri 原生支持透明、无边框、置顶、跳过任务栏和多窗口，适合桌宠窗口。
- 控制台与 Live2D 渲染都可使用同一个 Vue/TypeScript 工程。
- Rust 层可以保管令牌、代理网络请求、控制窗口和系统托盘，避免把高价值凭据留在 WebView 的 localStorage。
- 安装体积和常驻内存通常比 Electron 更适合长期运行的桌宠。

Tauri 的透明窗口、`alwaysOnTop`、`skipTaskbar`、窗口状态等能力均有正式接口。Windows 透明窗口需专门验证白闪、阴影与 WebView2 组合行为。

### Live2D 与桌宠行为

采用 **Petra 的分层架构**：渲染、桌宠自主行为、助手界面分别隔离。标准 Live2D 后端使用 `pixi-live2d-display` + Pixi 6，并加载官方 Cubism Core；这与 Petra 0.2.3 的标准模型后端一致，也能直接加载当前的 `seethrough_output.model3.json`。

Molly 只移植 Petra 中与桌宠相关的安全能力：随机眨眼/动作调度、气泡、视线与后续漫游模块。Petra 原项目的任意命令、启动本机应用、关机、文件删除、前台窗口读取等助手工具不进入本项目。引入或改写的部分在安装包中附带 MIT 许可证与固定提交归属。

所有 sub2api 请求从 Rust 发出，WebView 只调用明确允许的 Tauri commands。这样不依赖 sub2api 的 CORS 白名单，也避免令牌暴露给渲染层。

## 6. 关键模块设计

### 6.1 透明模型窗口

- `transparent: true`、`decorations: false`、`alwaysOnTop: true`、`skipTaskbar: true`。
- 默认进入点击穿透，避免阻碍用户操作其他程序。
- 托盘菜单和可配置全局快捷键切换“交互模式”；交互模式下可拖动、缩放和唤出控制台。
- 保存每台显示器、DPI 和工作区对应的窗口位置；显示器移除后自动把窗口拉回可见区域。
- 默认播放 Idle，自动眨眼；登录成功播放 Nod，网络或鉴权失败播放 Shake。
- 动作优先级：故障反馈 > 用户触发 > Nod/Shake > Blink > Idle。动作结束回到 Idle。
- 物理计算跟随渲染帧；窗口隐藏或系统锁屏时暂停，恢复时重置时间差，避免物理爆跳。
- 首版目标 60 FPS；设置中允许 30/60 FPS，DPR 上限默认 2。4K 纹理需重点测显存和低功耗设备。
- WebGL context lost/restored 必须可恢复模型，不要求用户重启应用。

“真正嵌入桌面图标层”的 WorkerW 方案不作为首版目标。首版语义是透明桌面覆盖层；后续若明确需要“仅在桌面可见、被普通窗口遮挡”，再做 Windows 专用模式。

### 6.2 控制台

页面结构：

1. 登录：服务地址、邮箱、密码、验证码、TOTP。
2. 概览：用户、余额、账户状态、活跃订阅数、今日/累计 Token、今日/累计实际费用、请求数、RPM/TPM。
3. 订阅：分组、日/周/月使用进度、剩余天数、到期时间。
4. API 密钥：名称、状态、所属分组、额度、有效期、最近使用、近期用量；密钥值默认掩码。
5. 用量：日期范围、Token/请求/费用趋势、模型分布和密钥筛选。
6. Molly 助手总开关：只负责启用或关闭；服务商、API Key、模型、人设和主动问候在桌宠窗口中配置。

控制台状态应明确区分“正在加载、无数据、离线、会话过期、服务端错误”，不能用空白或 0 冒充未知值。

### 6.3 登录和会话

首版流程：

1. 校验用户输入的服务根 URL；生产环境只允许 HTTPS，本机开发例外。
2. 请求 `/health` 与 `/api/v1/settings/public`。
3. 根据公开设置呈现 Turnstile、腾讯验证码或阿里云验证码组件。
4. 将邮箱、密码和一次性验证码证明交给 Rust，Rust 直接请求 `/auth/login`。
5. 若返回 `requires_2fa`，进入 TOTP 页面并调用 `/auth/login/2fa`。
6. access token 仅保存在 Rust 内存；refresh token 保存在 Windows Credential Manager。
7. 提前刷新 access token；多个并发 401 只触发一次 refresh。新 refresh token 落盘成功后才废弃旧值。
8. 登出时先尽力调用 `/auth/logout`，随后无条件清除本地会话。

密码不保存、不写日志、不进入前端持久状态。若目标站点启用的验证码无法在 Tauri WebView 的来源下正常运行，则改用系统浏览器登录 + PKCE + 一次性授权码交换；该方案需要在自有 sub2api 项目增加桌面授权入口。

后续版本再支持 GitHub、Google、LinuxDo、微信、OIDC、钉钉和 Passkey 等登录方式，优先通过系统浏览器完成，不在内嵌窗口截获第三方凭据。

### 6.4 API 数据层

- Rust 统一增加 Bearer token、超时、请求 ID、错误映射和日志脱敏。
- 只读 GET 可对网络错误做最多 2 次指数退避重试；登录、刷新、登出不自动盲目重试。
- 对 `{ code, message, data }` 做统一解包，并在 TypeScript 边界使用 Zod 做运行时校验。
- `/auth/me` 与用量概览每 60 秒刷新；订阅每 5 分钟刷新；密钥按页面进入或手动刷新读取。
- 重查询接口遵守上游 Heavy rate limiter，不进行高频轮询。
- 401 先做单飞刷新；刷新失败才切到登录页。403、429、5xx 和离线分别展示不同状态。
- 每次升级 sub2api 前运行契约测试；不直接复制其整套前端代码。

### 6.5 Molly AI 助手

- AI 默认走 MollyCloud 的 OpenAI 兼容入口 `https://mollycloud.cn/v1`，也可在桌宠窗口配置 Petra 风格的第三方或自定义 OpenAI 兼容服务；调用产生的 Token 正常计入所选密钥。
- Rust 从用户接口读取完整密钥并直接发起模型调用，WebView 只收到密钥名称、ID 和尾号。登录 JWT、Refresh Token 与完整 API Key 永不进入提示词或前端存储。
- 首批工具严格限定为 `get_account_overview`、`get_subscription_status`、`get_usage_summary`、`get_api_key_status`。工具结果按字段白名单裁剪，不把任意服务端 JSON 原样交给模型。
- 助手不能充值、购买订阅、修改/创建/删除 API 密钥，也不能执行系统命令。充值只由本地规则提示，用户点击后打开 `https://mollycloud.cn/purchase` 自行完成。
- 低余额阈值可由用户配置；订阅剩余 3 天以内提示。相同提醒至少 12 小时不重复。
- 支持按 5–120 分钟间隔主动问候；设置界面明确提示会产生少量 API 用量。当前不读取或发送前台窗口内容。

## 7. 安全基线

- refresh token 存 Windows Credential Manager；access token 只存内存。
- API 密钥列表不持久化，默认掩码；显示和复制只能由用户明确触发。
- 日志禁止出现密码、Authorization、refresh/access token、验证码、完整 API key。
- Tauri capabilities 使用最小权限；WebView 禁止任意 shell、文件系统和任意 URL 访问。
- AI 工具采用服务端白名单；不移植 Petra 的 `run_shell`、关机、文件删除和前台窗口读取能力。
- CSP 只允许本地资源和确需的验证码来源；外部链接交给系统浏览器。
- 服务 URL 建立允许域配置；禁止静默降级 HTTP、忽略证书错误或任意重定向到其他主机。
- 更新包必须签名；Windows 正式发布使用代码签名证书。
- 单实例运行，第二次启动只唤起控制台。
- sub2api 使用 LGPL-3.0；若复制或修改其源码，需要保留许可证并按 LGPL 履行义务。仅调用公开 HTTP API 仍需在发布前完成一次许可证审查。
- Cubism Core 不在公开 GitHub Framework 中；构建所需 SDK 必须来自 Live2D 官方分发包。打包模型和 SDK 前审查 Live2D SDK 与模型素材的发布许可。

## 8. 里程碑与完成标准

### M0：契约与资源冻结

任务：

- 确认正式 sub2api 站点 URL、测试账号、是否启用验证码/2FA、是否允许增加桌面授权接口。
- 将 sub2api API 契约固定到已部署版本，而不是盲目追踪 `main`。
- 建立模型导入脚本、引用校验与哈希清单。
- 确认 Live2D SDK for Web 官方包及发布授权。

退出条件：模型资源校验全绿，测试环境可登录，API 响应样本已脱敏保存为测试 fixture。

### M1：桌面壳与双窗口

任务：

- 初始化 Tauri 2 + Vue 3 + TypeScript。
- 创建 console、overlay 两个入口。
- 完成系统托盘、单实例、窗口状态恢复、置顶和穿透开关。

退出条件：安装包启动后只有模型窗口常驻；托盘可打开/关闭控制台，重启后位置正确。

### M2：Live2D 运行时

任务：

- 接入官方 Cubism Web SDK。
- 加载模型、纹理、物理和四组动作。
- 完成动作调度、窗口拖拽、缩放、DPI 与 context 恢复。

退出条件：透明背景无白框；Idle/Blink/Nod/Shake 可重复播放；连续运行与睡眠恢复无崩溃。

### M3：认证与本地安全

任务：

- Rust HTTP 客户端、URL 校验、响应解包、错误分类。
- 邮箱密码、验证码、TOTP、刷新、登出。
- Windows Credential Manager 和日志脱敏。

退出条件：登录态跨重启恢复；token 轮换和并发 401 正常；日志与 WebView 存储中没有凭据。

### M4：只读用户控制台

任务：

- 概览、订阅、API 密钥、用量趋势和设置页面。
- 统一加载/空/错/离线状态，轮询和手动刷新。
- 站点与客户端数值对照测试。

退出条件：余额、订阅、密钥、Token 和费用与站点在同一时间窗口内一致；无权限越界接口。

### M5：联动与体验完善

任务：

- 登录成功、离线、低余额和错误状态驱动模型动作。
- 融合 Molly AI 对话页、只读账户工具、桌宠气泡和本地低余额/到期提醒。
- 全局快捷键、开机启动、主题、国际化和无障碍。
- 崩溃恢复、诊断导出（强制脱敏）。

## 9. 测试与验收清单

### 功能

- 同一站点账号可以登录；验证码和 TOTP 流程可用。
- 会话过期可无感刷新，refresh token 失效后明确要求重新登录。
- 余额、订阅、密钥状态、Token、请求数和费用与站点一致。
- 模型透明显示，置顶、穿透、拖动、缩放和显隐可控。
- 四组动作与物理可用；断网不会导致渲染卡死。

### 安全

- 本地日志、崩溃报告、localStorage、配置文件不含密码和 token。
- API key 默认掩码，复制行为有明确反馈；退出登录后内存数据清空。
- 仅连接用户配置且验证通过的 HTTPS 主机。
- Tauri IPC 无任意 URL、任意文件或任意命令执行入口。

### 质量

- 冷启动能看到模型加载进度或占位状态，不出现白色矩形闪烁。
- 多显示器变化后窗口不会丢失在屏幕外。
- 4096 纹理在目标低配机上性能达标；不达标时提供 2048 纹理构建档。
- 运行 8 小时无持续内存增长；WebGL 丢失后能恢复。
- 关键 API 有 fixture 单测和真实测试环境的契约测试。

## 10. 开工前需要锁定的项目输入

以下信息不影响本计划成立，但在 M0 开始时必须确定：

1. 桌面客户端正式名称、图标和 Windows 包标识。
2. 自有 sub2api 的正式域名与测试环境域名。
3. 目标站点当前启用的验证码、2FA 和第三方登录方式。
4. 是否允许在自有 sub2api 增加桌面授权码接口；若不允许，首版只支持邮箱密码 + TOTP。
5. API 密钥首版只展示状态，还是需要允许显示/复制完整值。
6. “出现在桌面”是否指常见的透明置顶桌宠，还是必须处于桌面图标层。
7. Live2D 模型与 Cubism SDK 的最终发布授权范围。
