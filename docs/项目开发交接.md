## 3. 最近完成的三项改动

### 3.1 系统时间作为常驻内容

入口为「灵动岛 → 显示与交互 → 常驻内容」，按钮顺序为实时网速、CPU / 内存、媒体与歌词、游戏 FPS、系统时间、自定义组合。

- “系统时间”可单独选择，显示本机 24 小时制时分秒。
- 自定义组合的三个位置均可以选择时间，与网速、资源、FPS 或媒体封面组合。
- 删除旧附加时间开关及额外 80px 时钟列，避免岛体被重复增宽。
- 默认独立时间尺寸为 150×34，默认组合为 260×42；读取用户已有宽高设置。
- 通知和任务活动临时覆盖常驻内容，结束后恢复当前模式；总开关与全屏隐藏优先，静默模式保留含时间的内容。
- 隐藏、覆盖或组件销毁时停止计时器；恢复显示时重新读取系统时间。

偏好：独立时间使用 `nsd_system_time`，组合使用 `nsd_custom_slots` 中的 `time`。存储桥接自动添加正式或预览前缀，不能直接把预览数据写入正式偏好。

旧 `nsd_show_system_time=true` 自动迁移到组合：原单内容保留并加入时间；已有组合优先使用空槽，三个槽均满时用时间替换第三项，前两项保留。迁移失败恢复原偏好并允许重试。

关键文件：`app/src/netspeed.ts`、`app/src/components/NetSpeedPanel.vue`、`vendor/netspeed-dynamic/frontend/systemClock.ts`、`bridge.ts`、`views/WidgetIsland.vue`。

### 3.2 上架但不可购买的套餐

根因是客户端此前读反了二开服务端字段；现已核对本机真实二开源码，而非仅参考原版 Sub2API。

| `for_sale` | `user_visible` | 展示 | 购买 |
| --- | --- | --- | --- |
| true | true | 显示 | 允许，仍需通过支付渠道和限额校验 |
| true | false | 完整显示名称、价格与权益 | 按钮“不可购买”，禁止选择 |
| false | true | 不显示 | 禁止 |
| false | false | 不显示 | 禁止 |

`for_sale` 控制上架目录，`user_visible` 控制允许新购买。两个普通用户接口 `/payment/plans` 和 `/payment/checkout-info` 已返回上架停售套餐及两个字段，**无需新增接口或部署服务端**。客户端下单前仍重新读取最新状态，原生校验继续保留。

关键文件：`app/src/payments.ts`、`app/src/payments.test.ts`、`app/src/components/RechargePanel.vue`、`app/src-tauri/src/payments.rs`。本轮未修改 Rust 支付逻辑，也未修改外部服务端仓库。

## 4. 开发与检查命令

环境需要 Windows、WebView2 Runtime、Rust stable 和 MSVC Build Tools。当前 Vite 8 的 Node 要求为 `^20.19.0 || >=22.12.0`；不要仅按旧 README 的“Node 20+”判断。

在 PowerShell 中使用 `.cmd` 入口可避免 npm 的 PowerShell 执行策略问题：

```powershell
Set-Location 'C:\Users\ititr\Documents\ChatGPT\molly宠物开发\app'
npm.cmd install
npm.cmd run dev:desktop
```

`dev:desktop` 会验证 24320 上的服务是否提供当前项目的 `App.vue`。匹配则复用 Vite 并跳过 `beforeDevCommand`；其他服务占用端口则退出，不自动停止占用进程。没有服务时，由 Tauri 执行 `npm run dev`，先构建三个工作台再启动 Vite。

**复用 Vite 不会重新构建内嵌工具资源。** 修改 vendor 前端后执行对应命令，普通 Vue 源码改动才直接热更新：

```powershell
npm.cmd run build:ccswitch
npm.cmd run build:image-workbench
npm.cmd run build:skills-manager
```

浏览器设计预览入口为 `http://localhost:24320/?ui-preview=console`，使用演示数据，不提供真实支付或 Agent 写入。单独启动前端可执行 `npm.cmd run dev`。

常用验证，在 `app` 目录执行：

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run check:design
npm.cmd run check:design -- --dark
npm.cmd run check:design -- --island-clock
npm.cmd run check:design -- --motion
```

原生支付专项，在 `app/src-tauri` 目录执行：

```powershell
cargo test --offline --lib payments::tests --jobs 1
```

只修改宿主 Vue 且三个工具资源已构建时，可作定向构建检查：

```powershell
npx.cmd vue-tsc --noEmit
npx.cmd vite build
node scripts/check-package-inputs.mjs --built
```

这组命令不会重新构建 vendor，不能替代工具源码变化后的完整构建。`--offline` 要求本机已缓存依赖。不要直接运行可能使用真实用户目录的上游后端测试。

## 6. 公共 UI 与模块边界

接手修改前先读根 `AGENTS.md` 及 `design-system/molly-desktop/MASTER.md`。

- 颜色和尺寸入口：`app/src/design-tokens.css`；组件主题：`app/src/theme.ts`；公共布局：`app/src/styles.css`。不能用单页覆盖修补导航、账户栏、字体或工作区。
- 标题栏与侧栏为连续外框，右侧工作区两个上角圆角；普通页无页级标题和介绍。
- 横向菜单以概览为标准，共用 `app/src/subnav.css`、`navigationMotion.ts`；新增分类沿用字体、滑动下划线、内容过渡和减少动态效果规则。
- 输入光标始终黑色；金额和套餐选中按钮使用完整荧光绿。滚动条仅区域悬停时显示，颜色浅，无两端箭头。
- Molly助手、CC Switch、生图为沉浸式内容页；CC Switch / 生图原版 UI 例外只限内嵌区域，不能改变宿主框架。
- 灵动岛和 Skill 管理器共用工具页布局，不显示宿主账户栏和账户提醒；保留公共内容边距，分别由内容区及 iframe 内部滚动。
- Petra 和灵动岛透明窗口各自独立，不能套用控制台背景、最小尺寸或滚动规则。
- 公共样式变化须检查登录及七页、三种尺寸、深浅主题；保留用户修改，不为设计检查重启桌宠。

数据与调用边界：

| 模块 | 必须保留的边界 |
| --- | --- |
| 账户与密钥 | 账户请求在 Rust；界面接收掩码，不能把账户令牌或真实密钥交给助手上下文 |
| 生图 | 独立来源 sandbox 与受限 MessageChannel；不注入通用 Tauri IPC；用户手动填写并保存密钥，不自动读取账户密钥 |
| CC Switch | 供应商库、设置、备份保持 Molly 私有；导入只入库，明确启用后才写本机工具配置；代理使用独立端口，不覆盖独立版数据 |
| Skill 管理器 | 私有库与明确选择的 Agent 目录分离；部署/删除来自用户操作，未受管理冲突文件保留 |
| 支付 | 原生金额、套餐、订单界面；支付验证用独立临时 InPrivate WebView2，不注入通用 IPC、不共享 Refresh Token |
| 灵动岛 | 随宿主启停，无独立自启动；偏好在 Molly 私有存储，预览使用独立前缀 |

现行 `AGENTS.md` 禁止注册或唤起外部 `ccswitch://`。历史更新日志中的外部协议关联流程不能作为重新注册的依据。

## 7. 插件架构与更新

入口为「设置 → 功能插件」。目录唯一入口是 `app/plugins/definitions.json`：

| 插件 | 上游版本 | Molly 适配版本 |
| --- | --- | --- |
| CC Switch | 3.20.4 | 3.20.4-molly.1 |
| 生图工作台 | 0.7.12 | 0.7.12-molly.1 |
| Skill 管理器 | 1.40.0 | 1.40.0-molly.1 |

当前宿主要求均为 `>=0.1.6`，每个插件有独立 `adapterApi`。灵动岛为固定内置功能，不加入此目录。

独立更新对象是 HTML/JS/CSS 资源包。CC Switch、Skills 等 Rust 适配器仍链接在主程序；原生 API 变化需要升级宿主，不能把上游独立 EXE 直接作为 Molly 插件运行。检查官方版本与下载经过适配的 Molly 包是两步，官方新版不等于已有兼容包。

插件记录在应用数据目录 `plugins/installed.json`，代码在 `plugins/packages/`。下载及安装验证固定来源、大小、SHA-256、清单和兼容性，失败不切换当前版本。卸载保留供应商、备份、技能库、已部署 Skills、生图数据及外部 Agent 配置，不缩小宿主 EXE；部分后台服务变化需要正常重启。

`npm.cmd run release:plugins` 仅生成 `artifacts/plugin-release/` 的 ZIP、`index.json`、`UPLOAD.md`，不自动上传。更新来源为 `https://desktop.veriolink.com/plugins/index.json`。具体事务和发布要求见 `docs/功能插件方案.md`。

R2 桶为 `mollycloud-desktop`。上传凭据留在发布者本机环境，不写进源码、交接文档、安装包或日志。`release:r2` 默认只生成本地清单，显式 `--publish` 才发布；安装器校验和公共地址验证成功后再更新 `latest.json`。命令和清单格式见 `docs/桌面端更新发布.md`。

## 9. 历史问题与继续开发时的重点

1. **安装启动全窗口未响应**：灵动岛同步插件命令中调用窗口显示触发插件锁重入，曾导致 UI 线程死锁。已改异步命令并通过主线程操作窗口，保留 Tauri 内部可见状态同步。不要改回同步 `show_window_no_activate`；回归须覆盖默认显示分支，不能只验证隐藏状态。
2. **停售套餐消失**：必须采用本交接第 3.2 节的二开字段语义，避免更新 Sub2API 适配时再次读反。
3. **内嵌界面修改不生效**：复用 Vite 时检查是否重建了对应 vendor 前端；若用户安装了插件更新，还要核对实际加载的适配版本与安装记录。
4. **CC Switch 升级回归**：保留官网地址 `https://mollycloud.cn` 与 API `/v1` 的用途区分、连通性和余额适配、私有数据库和实际工具配置边界。执行 `npm.cmd run check:ccswitch-upgrade`，详细用例见内置方案。
5. **安全软件历史报告**：火绒曾拦截 Cargo 的 Skills 测试二进制。已移除自复制和独立 CLI bridge，管理 CLI 使用宿主明确参数。不得根据一次受信任环境运行声称误报已解决；当前代码签名和复扫边界见 Skills 方案。
6. **发布前真实联调**：模拟订单、浏览器布局和组件替身不证明实际渠道付款、真实媒体/FPS 或升级安装已经通过，按发布范围补做相应验证。

第 12 节六项布局已完成；最新功能与验证见第 13 节。下一次工作应根据用户的新需求继续，不重复实现已移除的 TTS / MCP 市场，不擅自重启、打包或发布。
