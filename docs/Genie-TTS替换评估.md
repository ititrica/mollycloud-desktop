# Genie-TTS 替换评估

评估日期：2026-09-16。用户认为原 Kokoro 音质不满意。初次评估核对 Genie-TTS 源码、PyPI 发布包、模型清单及公开问题；随后完成官方预设的本机 A/B 合成。用户已试听并选择 **A：官方中文预设基础配置**，开发代码已接入该配置，具体实现见 `本地语音内置方案.md`。

## 建议

把 **Genie-TTS + GPT-SoVITS V2ProPlus 中文角色模型 + 中文 RoBERTa 特征**作为替换候选，优先验证中文自然度、短句、数字和中英混读。它允许为角色指定参考音频及对应文本，适合调节 Molly 的音色和语气；最终效果取决于具体角色模型、参考录音及文本前端，不能仅凭更换推理引擎保证改善。

先对同一批 Molly 对话生成试听样本并比较首句延迟、热启动速度和内存，再确定默认音色与正式接入配置。当前功能测试证明 Kokoro 能运行，但用户反馈说明还需要主观音质验收。

## 已核对的版本

- GitHub 默认分支 `master`，固定提交 `d347fd0f8683e9a362b69f59fa0a4799ddb5e828`，2026-08-30。
- PyPI 最新版本仍为 `2.0.2`，wheel 上传时间 2025-12-12，约 490 KB；版本号与当前源码相同，不代表内容相同。
- 当前源码包含中文遇英文字母时自动进入中英混合模式，以及多种 RoBERTa 输入/输出布局、资源目录的兼容逻辑。已下载并检查的 PyPI wheel 没有这些改进。
- 支持 GPT-SoVITS V2 / V2ProPlus；README 尚未列为支持的 V3 / V4 不能直接沿用。
- 运行依赖 Python ≥3.10、ONNX Runtime 1.22.1、ONNX、NumPy 及发音前端等；官方推理默认使用 CPU。模型转换才需要 PyTorch，集成预转换模型无需为用户安装完整训练环境。

因此，后续接入应固定已审查的源码与依赖版本，自行构建运行包，不能只执行 `pip install genie-tts` 后视为完成升级。

## 实际资源体积

依据 Hugging Face `High-Logic/Genie` 的文件清单，模型仓库提交 `52b17272e0b7032415e85ad37b551db2386b1810`。以下为文件字节数，使用十进制 MB，不是最终压缩下载包或运行内存：

| 组成 | 字节数 | 大致大小 |
| --- | ---: | ---: |
| 全部基础 GenieData | 410,517,475 | 410.5 MB |
| 一个现成中文角色：菲比 V2ProPlus（含参考音频） | 336,374,499 | 336.4 MB |
| 原仓库可选中文 RoBERTa 及 tokenizer | 599,527,261 | 599.5 MB |
| 上述合计 | 1,346,419,235 | 1.35 GB |

上述不含 Python 和依赖。可以精简不用的语言资源，但不能在实测前宣称完整资源仍只有 README 中的约 230 MB 模型或约 200 MB 运行环境。

当前 `download_genie_data()` 会额外调用 `download_roberta_data()`，默认下载另一仓库的 FP32 RoBERTa（模型约 1.198 GB）；按这个默认路径加中文角色，资源会约为 1.945 GB。该仓库另有约 599 MB 的 FP16 版本，仍需验证 CPU 支持、速度和实际中文特征输出；不能只改文件名就切换。

官方 GUI 整合包 v2.0.2 压缩文件约 1.93 GB，Molly 无需嵌入这个独立 GUI。

README 的 1.13 秒首推数据基于 i7-13620H 上 100 条约 20 字的日文句子，不是 Molly 中文、当前 V2ProPlus + RoBERTa 配置的实测。源码会在加载时把多项 FP16 权重转成 FP32，运行内存还需独立测量。

## 接入 Molly 的具体变化

1. 复用现有回复事件、全应用单一播放器、音量、停止、错误反馈和口型联动。Genie 常用 32 kHz 输出，播放器解码本身支持；后端需正确封装 WAV，保留过期请求丢弃。
2. 把语音工作进程改为私有的 Python 推理进程，随语音运行包附带解释器和锁定依赖，普通用户无需自行安装 Python。继续用私有管道通信，无需启用官方 FastAPI 服务。
3. 下载按基础资源、角色模型、中文特征分类记录校验摘要，确保模型与参考音频路径固定。`GENIE_DATA_DIR`、缓存和临时文件全部指向 Molly 私有数据目录；首次下载仍由 Molly 设置界面处理。
4. 确认中文 RoBERTa 真正加载、特征维度正确。当前源码在缺少或加载失败时会退回全零 BERT 特征，因此“生成了声音”不能作为高音质配置已经启用的证据。
5. 音色设置改为角色/预设 ID；Kokoro 的 0–102 音色编号不能直接迁移。每个 Genie 音色需要匹配的模型及参考音频/文本。
6. 上游 `tts()` / `tts_async()` 没有暴露与当前 Kokoro 对应的语速参数。需要验证模型导出能否支持，或实现保持音高的变速；不能保留一个不起作用的语速滑块。
7. 继续控制单句长度、串行推理、空闲释放和停止后清理。当前的流式接口按句产生音频，不能据此承诺任意长句都能立即开始播放。

## 音质验收重点

推荐先采用上游预置中文角色作技术试听样本，再确定 Molly 的正式声音。每组使用相同文本与固定参考配置，多次生成检查稳定性：

- 日常长句：自然度、停顿、情绪是否接近所需角色。
- 极短回复：“好。”“你好。”“嗯，一定。”——避免噪声、漏读或重复参考音频。
- 中英混读：“你好，我是 Molly。”“Codex 已经完成任务。”
- 金额日期：“余额是 128.50 美元，今天是 2026 年 9 月 16 日。”
- 多音字、问句和连续多段回复；生成中停止后，下一段应正常开始。

上游有中文断句/语调异常、短句模糊和中文 G2P 崩溃等公开反馈。这些是用户报告，本轮未在本机复现；应作为验收用例，不能直接断言当前固定提交全部仍存在，也不能忽略。

## 官方预设 A/B 本机结果（2026-09-16）

已下载并校验固定版本的基础资源、菲比 V2ProPlus 官方 Normal 预设和原仓库可选 RoBERTa，共 33 个文件 / 1,346,419,235 字节。运行环境独立保存在 `artifacts/tts-genie/`，没有写入 Molly 用户配置、重启桌宠或生成新安装包。

CPU 为 i5-12600KF，系统内存约 32 GB；使用 Python 3.12.10、ONNX Runtime 1.22.1、CPUExecutionProvider，每个 session 限制 4 个线程。两个子进程顺序运行，种子均为 42，合成期间禁止 Python socket 外连。测试不调语速、不归一化音量。

| 指标 | A：官方预设基础配置 | B：同预设 + 中文增强 |
| --- | ---: | ---: |
| 适配后成功样本 | 9/9 | 9/9 |
| 有效中文特征非零元素数 | 0 | 28,672（28 × 1,024） |
| 峰值进程 working set | 5.12 GiB | 6.45 GiB |
| 本次初始化时间 | 20.839 秒 | 12.152 秒 |
| 后续 8 条首分句就绪耗时中位数 | 1.817 秒 | 2.037 秒 |
| 后续 8 条完整生成耗时中位数 | 2.686 秒 | 2.898 秒 |

上述只是一台机器上的单轮对照，样本长短不一。初始化时间受到文件缓存和系统负载影响，不能据此得出增强配置加载更快的结论。内存显著高于轻量方案；需结合用户听感决定额外资源是否值得。

初始直接调用上游推理的两组均 8/9 成功，“嗯，一定。”在 `ToneSandhi` 中因空韵母索引出现异常，之后的样本仍能生成。最终试听增加了相同的兼容处理：使用官方分句器并保护小数点，将“嗯”按近音“恩”合成。后者是明确记录的发音替代，尚不是保留原始鼻音的完整修复。

适配后 18 条音频均为 32 kHz / mono / PCM16，非空、有限值且无削波；基础组明确关闭 RoBERTa，增强组加载成功并验证非零特征，未静默降级。这些检查证明运行成功，不能代替人耳判断自然度、读音与漏字。

- 最新试听页及完整数据：`output/tts-genie-audition/2026-09-16-feibi-adapted/`。
- 初始原始结果：`output/tts-genie-audition/2026-09-16-feibi/`。
- 可复现的下载脚本、资产摘要、依赖锁及合成脚本：`scripts/tts-genie/`。

用户已选择 A。开发代码使用私有、可分发的 CPython 运行包（约 90 MB），首次仅下载基础及菲比资源约 747 MB。音量、自动朗读、停止与嘴型链路复用，语速固定自然速度并移除无效滑块；旧设置保留音量并迁移音色。设置入口按用户要求移到 Molly 助手齿轮菜单的「小助手设置」，控制台通用设置不再显示语音控件。

已通过 5 项 Rust 语音测试、6 项前端分句/播放器测试及 2 项安装资源检查测试。实际内置 Python + 隐藏 WebView2 的 9 项检查通过，涵盖安装、设置、真实 WAV 解码与播放调度、合成中停止、拒绝过期请求、停止后重新朗读和卸载。测试采用临时中文及空格目录，真实桌宠未重启。最终设置位置的深浅主题回归和生产构建见对应日志。

## 可选 GPU 加速（后续改动）

按用户要求加入通用、默认关闭的 GPU 开关，使用 ONNX Runtime DirectML 1.22.0，适配支持 DirectX 12 的 NVIDIA、AMD、Intel 显卡，不需要 CUDA。完整上 GPU 的 Genie 语义解码因频繁的 NumPy / GPU 数据传输变慢，因此最终只用 GPU 加速 VITS，保留其他步骤在 CPU。

运行包变为约 102 MB，模型仍为同一 747 MB 菲比基础资源，不引入 RoBERTa。已安装的模型更新时逐项验证并复用；开关遵循保存/取消，界面显示实际执行后端与回退状态。GPU 初始化失败或设备丢失会回退 CPU，关闭开关后释放旧进程。

本机 RTX 3070 Ti 对照中两组各 9/9 成功，后续 8 条完整合成时间中位数 CPU 2.66485 秒、GPU 1.7186 秒（约缩短 35.5%）。初始化失败和运行中设备丢失均通过连续两句回退测试。数据和音频在 `artifacts/tts-genie-gpu/verification/`；显卡节点实际执行由初次 ONNX profile 验证。AMD / Intel 尚未实机测试，不能把本机速度推广到所有设备。

设置入口仍为 Molly 助手齿轮 →「小助手设置」→「本地语音」，浅色与深色各 46 项检查通过，覆盖三种窗口尺寸、GPU 默认关闭、临时试听、取消、保存和回退提示。当前 GPU 改动尚未另行生成安装包。
