# MollyCloud 桌面端设计规范

版本：2026-09-17 · 当前实施规范

适用范围：登录、两步验证、登录协议，以及概览、订阅、API 密钥、用量、Molly助手、CC Switch、生图工作台、MCP 市场八个控制台页面。本文件取代早期紫粉色、科幻字体方案，是后续界面修改的统一依据。2026-09-16 按用户要求增加共享深色主题。页面细则只能补充内容布局，不能覆盖公共框架。CC Switch 和生图工作台的原版 UI 例外仅限各自独立内嵌内容区。

## 1. 设计目标与实现入口

浅色界面使用浅色背景、深蓝文字、浅绿交互强调和克制的中性边框；深色界面使用深蓝灰背景、浅色文字及相同的浅绿强调。两种主题共用布局、字体与组件规则。数据优先，装饰服务于分组，页面切换时公共界面保持稳定。

| 职责 | 唯一维护入口 |
| --- | --- |
| 色彩、字体、圆角、阴影、公共尺寸 | `app/src/design-tokens.css` |
| Naive UI 组件主题与状态 | `app/src/theme.ts` |
| 公共框架、组件布局与响应式规则 | `app/src/styles.css` |
| 页面内容、语义与交互 | `app/src/App.vue` |
| CC Switch 内嵌容器与导航桥接 | `app/src/components/CcSwitchPanel.vue` |
| CC Switch 原版内容 UI 与宿主适配 | `vendor/cc-switch/frontend/src` |
| 生图工作台容器、存储与请求 | `app/src/components/ImageWorkbenchPanel.vue`、`app/src/imageWorkbench.ts`、`app/src-tauri/src/image_workbench.rs` |
| 生图工作台原版 UI 与适配 | `vendor/gpt-image-playground/src` |
| 主题接入 | `app/src/main.ts` |
| 外观偏好、系统主题与持久化 | `app/src/appearance.ts` |
| 页面回归检查 | `app/scripts/verify-design.mjs` |

组件主题读取 CSS token 并转为颜色字面值。Naive UI 会在 JavaScript 内计算派生颜色，不能把 `var(--color-…)` 直接传入需要颜色运算的主题字段。

关闭 Naive UI 默认 preflight，由公共 CSS 管理文档字体；不能仅设置 `common.fontFamily` 后假定正文已同步。开发和生产入口都要检查实际计算字体。

使用规则：

- 主按钮配深绿色文字，不能用白字叠在浅绿底上。辅助文字不能直接使用亮绿色。
- 选中导航通过浅绿色整块背景、深色文字和绿色图标表示，不依赖贴边色条。
- 普通卡片四边使用同一中性颜色。语义色放在图标、数字、状态标签或容器内部的有界区域。
- 余额和订阅到期提示属于同一种账户提醒，使用相同浅绿表面；错误提示使用错误色。
- 不为某个菜单页面重新定义背景色、导航字体或主题色。

### 深色与系统外观

默认选择“跟随系统”，实时响应系统浅色/深色变化；用户指定浅色或深色后不再受系统变化影响。共享 token 通过根节点 `data-theme` 切换，Naive UI 同步切换基础主题并重新读取颜色字面量。登录、两步验证、协议、全部控制台页面、下拉选单和各设置弹层一并变化。Petra 透明窗口不接入控制台主题。

深色核心值为工作区 `#141a21`、侧栏 `#171e26`、卡片 `#1d2630`、次级表面 `#222d39`、主文字 `#e5edf5`、次文字 `#b0bfd0`、边框 `#303e4d`；主按钮继续使用 `#b4e976` 与深绿文字。语义表面、玻璃蒙层、登录插画背景和聊天背景也由同一 token 文件维护，不能追加页面专属深色覆盖。

侧栏底部仅保留设置按钮，不再提供独立太阳/月亮主题切换按钮；紧凑侧栏中设置图标与导航图标保持统一尺寸和对齐。设置弹层的“外观”提供“跟随系统 / 浅色 / 深色”原生单选组，遵守草稿、取消与保存规则。偏好保存在当前应用来源的 `mollycloud:appearance`；设计预览使用独立的 `mollycloud:preview:appearance`，不写桌面偏好。写入失败保留当前主题并显示错误。

生图工作台复用原版媒体查询深色样式，通过 iframe 继承的 `color-scheme` 跟随宿主，保留原有 sandbox 与 MessageChannel 边界。CC Switch 复用原版深色 class 和组件主题，在现有同源嵌入边界内监听宿主 `data-theme`；内嵌设置提示外观由控制台管理，不写独立版或内置旧主题偏好、不设置原生窗口主题。主题切换不能重载 iframe 或丢失编辑状态。

### 字体与文字层级

正文统一使用 `--font-body`：Segoe UI Variable Text → Segoe UI → Microsoft YaHei UI → PingFang SC → sans-serif。中文和英文均保持无衬线外观，不加载独立的页面字体。

| 内容 | 规范 |
| --- | --- |
| 页面标题 | 32–42px，700，行高 1.15 |
| 页头说明 | 15px，行高 1.6，次要文字色 |
| 导航文字 | 16px，600 |
| 内容标题 | 普通分组 17–21px；用量构成和聊天工具栏 24–27px |
| 表单、表格、说明 | 13–16px，依信息密度选择 |
| 关键统计数字 | 22–40px，700 左右，等宽数字特性 |
| 密钥、API 端点、验证码 | `--font-mono`，Fira Code / Cascadia Mono / Consolas |

金额和统计值以正文字体配 `font-variant-numeric: tabular-nums` 为主。金额精度和币种由业务格式化函数控制，不能为排版修改金额含义。长消息允许换行；单行名称可以省略，但不能挤占操作按钮。

## 3. 公共框架：所有菜单页面必须相同

`.app-shell`、`.sidebar`、`.topbar`、`.page-content` 是共享框架。不能新增 `.app-shell--usage`、`.app-shell--assistant` 等规则改变导航或外部布局。`.workspace--assistant` 只负责固定高度和滚动行为。Molly助手、CC Switch 与生图工作台是明确的沉浸式工具页例外：保留公共侧栏，但隐藏宿主顶部栏、账户提醒和页级错误条，让内嵌页面占满右侧工作区。

| 项目 | 规范 |
| --- | --- |
| 框架高度 | `100dvh`，最小窗口 960×640 |
| 侧栏宽度 | `clamp(210px, 18.4vw, 266px)`；窗口宽度 ≤1180px 时 210px |
| 侧栏内边距 | 上 32px、左右 16px、下 24px |
| 自绘标题栏 | 高 32px；左侧只放菜单栏切换按钮，不显示品牌图标或名称，右侧保留窗口控制 |
| 侧栏品牌栏 | 高 72px；MollyCloud 图标与英文品牌名和下方导航对齐，不显示中文品牌名 |
| 导航按钮 | 高 56px、圆角 14px、左右内边距 14px、图文间隔 12px |
| 导航按钮间隔 | 10px |
| 内容最大宽度 | 1440px |
| 页头和内容左右内边距 | 普通页面为 `clamp(24px, 2.7vw, 40px)`；沉浸式工具页为 0 |
| 页头 | 普通页面最小高度 164px；上 36px、下 20px；沉浸式工具页不显示 |
| 高度 ≤760px 的页头 | 最小高度 134px；上 22px、下 12px |
| 正文顶部间距 | 12px |
| 余额按钮 | 178×64px，所有页面都显示钱包图标 |
| 用户按钮 | 高 64px；宽度 ≤1180px 时收为 64px 头像按钮 |

普通页面工作区预留稳定滚动条槽，避免有滚动条和无滚动条页面之间左右跳动。页头透明，与工作区背景融为一体。沉浸式工具页由聊天记录区或 iframe 内部负责滚动，外部工作区不留边距。导航当前项提供 `aria-current="page"`，使用原生按钮保证 Enter/Space 操作。

普通页面的账户余额与用户容器顶边、底边保持水平对齐。刷新按钮位于用户容器正下方，右边缘与用户容器右边缘平齐，并使用稳定的 8px 垂直间距；刷新按钮不能参与顶部操作区高度计算而把用户容器向上抬高。

不根据当前页面调整侧栏 padding、nav gap、导航高度、标题字体、余额按钮形状或用户按钮尺寸。响应式调整必须按窗口条件对所有页面同时生效。

控制台使用 32px 自绘标题栏。用户通过标题栏最左侧、与 Codex 同类位置的“收起菜单栏”按钮切换紧凑模式；标题栏不显示 MollyCloud 图标或名称，并在右侧提供最小化、最大化/还原和关闭窗口控制。关闭操作继续遵循控制台设置，不能绕过退出或最小化到托盘策略。

侧栏品牌栏只显示 MollyCloud 图标和英文“MollyCloud”，与下方导航内容水平对齐且不显示中文。紧凑模式在所有九个菜单页统一将侧栏收为 76px，保留品牌图标并隐藏品牌文字，同时只保留导航与设置图标。切换按钮不绘制常驻边框或底色，只有指针悬停时显示较深的浅绿色容器底色；键盘焦点继续使用公共焦点环。隐藏的导航文字必须继续作为原生按钮的可访问名称和悬浮提示。再次点击恢复标准侧栏，不能改变当前页面、嵌入页状态或控制台设置。

控制台“设置”入口固定在侧栏底部，使用与导航一致的 56px 高度、14px 圆角和图文间距，但不作为菜单页面或改变当前导航选中项。侧栏采用纵向 flex，底部区域以 `margin-top: auto` 定位；空间不足时只有导航列表可滚动，设置按钮保持可见。高度 ≤680px 时，所有页面统一将顶部项目栏收为 64px、侧栏下内边距收为 16px、设置上方留白收为 16px，使九个入口通过导航区滚动适配最小窗口，导航高度和间距不变。

## 4. 圆角、边框与交互

基础间距为 4 / 8 / 16 / 24 / 32px；密集数据区域允许 12px 间隔。相邻、同职责控件使用一致间隔。

| 组件 | 圆角 / 尺寸 |
| --- | --- |
| 普通卡片、统计卡片、聊天外框 | 20px |
| 导航、标准按钮、输入框、提醒 | 14px |
| 小按钮、图标底板、小型状态区域 | 10px |
| 协议弹窗 | 24px |
| 状态标签、进度条 | 胶囊圆角 |
| 小 / 中 / 大按钮 | 32 / 44 / 52px 高 |
| 登录输入框、聊天输入框 | 56px 高 |
| 复选框 | 16px 方框，4px 圆角 |

边框只能由一层负责：

- 自定义外边框的 `NCard` 设置 `:bordered="false"`，账户 `NAlert` 同样关闭内建边框。
- 不叠加 Naive UI 内层边框、自定义 border 和彩色 inset shadow。
- 卡片内容区域的实际类名是 `.n-card-content`，不是 `.n-card__content`。优先用直接子元素选择器，避免修改嵌套卡片。
- 圆角容器内存在着色背景、伪元素或绝对定位层时，设置 `overflow: hidden`。键盘焦点画在外层控件上，不能一并遮掉。
- 不在圆角卡片顶部或左侧单独绘制彩色边，不用高亮模糊光晕掩盖边缘问题。
- API 表格只保留水平分隔线，禁止恢复竖向分割线。

普通卡片采用 `--shadow-card`，悬浮层采用 `--shadow-float`。悬停以颜色或中性边框变化反馈，不整体移动导航、卡片和按钮。动画以 180ms 为基准，尊重 `prefers-reduced-motion`。

键盘焦点采用 2px 深绿 outline + 2px offset；输入和复选框通过统一 `--focus-ring` 表示焦点。加载时保留按钮尺寸；禁用时保留可辨认文字。

## 5. 登录和协议

复选框行按 24px 行高排版。16px 方框居中于标签的第一行，即上下各留 4px；禁止添加额外 `margin-top` 或用负外边距补偿。

选项区域以 8px 间隔排列“自动登录”和协议勾选行。标签换行时，方框仍与第一行居中，而不是和整个多行文本块居中。

协议链接使用继承字体和行高的行内原生按钮，不嵌入具有独立高度的 `NButton`。链接点击及键盘事件不应冒泡导致协议复选框被误选。必须验证：

1. 点击标签和按 Space 能切换复选框。
2. 用 Enter 打开协议时不自动勾选同意。
3. 协议默认勾选；用户可取消勾选。打开或关闭协议不改变当前选择，弹窗中的“我已阅读并同意”可重新勾选。
4. 表单变窄、错误提示出现时仍对齐，登录区可纵向滚动。

两步验证沿用相同表单宽度、输入框和主按钮规范。自动登录仍由用户选择；勾选后仅把刷新令牌保存到 Windows 凭据管理器，不保存密码。必须启用 keyring 的 `windows-native` 功能，并序列化控制台与桌宠的令牌刷新。不得用默认的内存后端冒充持久保存。

### 控制台设置弹层

点击侧栏底部“设置”打开居中悬浮选单。选单宽度为 `min(560px, 100vw - 64px)`，最大高度 `100dvh - 64px`，圆角 24px；头部与底部操作栏固定，内容超长时内部滚动。沿用共享字体、浅绿选择状态和按钮主题，不更换公共导航外观。

选单通过独立的 `#console-settings-layer` 呈现，遮罩对其后的控制台应用 9px 背景模糊、轻度降低饱和度及浅色透明蒙层。只模糊背景，选单正文保持清晰。打开时控制台设置 `inert`，焦点限制在选单内；关闭动画结束后焦点回到设置按钮，不能让键盘进入背后的 CC Switch iframe。

“关闭窗口”使用一组原生单选框：“退出程序”与“最小化到托盘”，默认后者。“系统启动”提供“开机自启动”及其从属的“启动后最小化到托盘”开关；后者仅在自启动开启时可选，关闭自启动时自动关闭。系统启动设置读取 Windows 当前注册状态并在同一次保存操作中更新。保存前仅修改草稿；取消、Escape 和点击遮罩均丢弃草稿。右下角固定“取消”和“保存”，保存过程中禁用关闭与重复提交；读取或保存失败显示内联错误，不关闭选单、不把失败当作成功。系统自启动更新后若配置文件保存失败，应恢复保存前的系统状态。

桌面设置保存到 MollyCloud 应用数据目录中的 `console-settings.json`。原生后端在文件成功替换后才更新关闭行为；点击控制台关闭按钮时，托盘选项隐藏控制台并保留桌宠，退出选项结束整个应用并执行正常退出清理。带专用启动参数的 Windows 自启动才应用“启动后最小化”，用户手动启动始终唤起控制台。应用采用单实例运行；再次启动时不创建第二套控制台或桌宠，而是显示、还原并聚焦现有控制台。托盘菜单的明确退出始终退出，设置不修改账户登录策略。浏览器设计预览仅写入专用预览存储，不能修改桌面设置。

上述关闭偏好仅在已进入控制台后生效。启动加载、登录和两步验证界面点击关闭时，始终通过正常退出流程结束整个 MollyCloud（包括桌宠窗口与后台服务），不最小化到托盘。退出登录后再次适用此规则；已保存的关闭偏好保持不变。原生关闭判断使用控制台同步的当前界面状态，不能根据桌宠后台刷新的 Token 判断是否已进入控制台。

## 6. 页面内容和滚动

### 概览

四张统计卡片统一为白底和中性四边框，通过内部图标与数字区分分类。余额右侧展示累计消费，点击关系与数据含义保持一致。今日用量为独立分组，不与累计数据混淆。

### 订阅与账户提醒

订阅条目使用共享卡片外观，展示状态、计划、系统分配用量、到期信息。进度条放在卡片内部；剩余数字标注“剩余天数”，避免和日期字段混淆。

余额提醒和订阅提醒的左右边缘与正文卡片对齐，采用相同边框、圆角、图标容器与操作按钮；禁止单独增加左侧强调边。

### API 密钥

API 端点使用浅绿有界区域，列表使用共享白色卡片。表格最小内容宽度为 933px，以保留完整的“导入到内置 CC Switch”操作名称；空间不足时表格内部横向滚动，不扩宽工作区。密钥内容省略，复制和导入操作保留明确名称。状态标签沿用统一胶囊外观。

指针悬停或键盘聚焦时以常态圆球的右上角为稳定锚点，通过缩放和透明度过渡向左下展开为更大的圆球，收回时反向过渡。圆内使用标签、主金额、分隔线和次级 Token 数值的清晰层级，完整显示“余额 3.72$”与“今日消耗 128,400 token”。余额低于 1 时不显示圆球详情，常驻横向胶囊并显示“余额不足”。入口和展开圆球分别同步到原生鼠标命中区域，系统缩放只转换一次。靠屏幕边缘时钳制到可见区，底部放不下时允许向上展开。数据不可用时不能显示为 0；未登录时隐藏整个入口。

余额和今日 Token 使用同一账户的数据，每 60 秒及登录状态变化时刷新。相关实现位于 `app/src/petra/ui/BalancePill.ts`，真实头部锚点由 `PetView.getHeadBounds()` 提供。使用独立 Vite 服务时可设置 `MOLLY_UI_URL` 并运行 `node scripts/verify-balance-pill.mjs`；默认检查地址为 `http://127.0.0.1:24324`，截图位于 `artifacts/balance-pill/`。


任务运行或等待输入时，余额小球移动到模型头顶并扩展为自适应宽度胶囊：左侧 40px 圆球显示余额，右侧显示当前步骤，最大宽度 280px，超长单行省略，不显示任务数量角标。正文使用现有桌宠字体和 12px 字号。思考时优先显示 Codex 已落盘的公开摘要标题原文，缺失时使用“正在思考”；命令完成等步骤使用“运行了命令”等状态。不会显示摘要正文或原始推理。任务期间悬停、聚焦、点击都不展开下拉详情，移除面板之间的透明命中桥；进入任务时立即收起已打开的圆球详情。外围光点与渐隐拖尾沿整个胶囊边缘以 4.8 秒周期绕行，使用随宽度变化的 SVG 轨道，不围绕左侧余额圆球单独旋转。完成、失败或停止后恢复原位置的小圆球及 148px 圆形悬停效果，未读终态不能延续任务胶囊。位置切换使用 220ms 过渡，所有动画尊重减少动态效果偏好。

浏览器预览只能浏览目录，安装和配置操作必须明确提示需要桌面端。安装前显示目标 Agent 和实际配置路径；展示“已检测到配置”而非推断 CLI 已安装。无安装模板的项目只提供来源文档和手动配置。任何“已安装”结果必须来自原生端，外部修改和等待授权应在条目内显示。
